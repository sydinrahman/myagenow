How to Calculate Age in SQL Databases: MySQL, PostgreSQL & SQL Server

By The My Age Now team · Published October 30, 2026 · 8 min read

Calculating someone’s age from a date of birth sounds like a five-minute job. Then you ship it, and a user who turns 18 tomorrow is already marked as an adult. This guide gives you queries that actually work in MySQL, PostgreSQL, and SQL Server, plus the traps that cause those off-by-one bugs.

The Quick Answer

All the examples below assume a simple table called users with a birth_date column of type DATE. Here’s the short version for each database:

Database Age in full years Watch out for
MySQL TIMESTAMPDIFF(YEAR, birth_date, CURDATE()) Don’t use DATEDIFF(...)/365; it drifts.
PostgreSQL DATE_PART('year', AGE(CURRENT_DATE, birth_date)) Cast to int if you don’t want decimals.
SQL Server DATEDIFF(YEAR, ...) minus a birthday check Plain DATEDIFF(YEAR, ...) is wrong.

Why Subtracting Years Fails

The tempting approach is to subtract the birth year from the current year:

-- Looks fine. Isn't.
SELECT YEAR(CURDATE()) - YEAR(birth_date) AS age FROM users;

This ignores whether the birthday has happened yet this year. Someone born on 15 December 1995 would be listed as 31 in January 2026, when they’re still 30 for almost another year. The same problem hits the “divide days by 365” shortcut: leap years pile up and the result slips by a day every four years or so.

Every correct method below does the same thing in spirit: count full years, and only count the current year if the birthday has already passed.

Calculating Age in MySQL

Age in years with TIMESTAMPDIFF

TIMESTAMPDIFF returns the number of complete units between two dates, which is exactly what age means.

SELECT
  id,
  birth_date,
  TIMESTAMPDIFF(YEAR, birth_date, CURDATE()) AS age
FROM users;

Age in years, months, and days

For a full breakdown, get total months first, then work out the leftover days from the last monthly anniversary:

SELECT
  id,
  TIMESTAMPDIFF(YEAR, birth_date, CURDATE())       AS years,
  TIMESTAMPDIFF(MONTH, birth_date, CURDATE()) % 12 AS months,
  DATEDIFF(
    CURDATE(),
    DATE_ADD(birth_date, INTERVAL TIMESTAMPDIFF(MONTH, birth_date, CURDATE()) MONTH)
  ) AS days
FROM users;

For someone born on 15 May 1990, checked on 31 October 2026, this returns 36 years, 5 months, 16 days.

The no-function-magic alternative

If you like seeing the logic spelled out, this version subtracts one year when today’s month and day come before the birthday’s:

SELECT
  YEAR(CURDATE()) - YEAR(birth_date)
  - (DATE_FORMAT(CURDATE(), '%m%d') < DATE_FORMAT(birth_date, '%m%d')) AS age
FROM users;

Calculating Age in PostgreSQL

PostgreSQL has the friendliest tool of the three: a built-in AGE() function that returns an interval.

Full age as an interval

SELECT id, AGE(CURRENT_DATE, birth_date) AS age
FROM users;
-- Example result: 36 years 5 mons 16 days

Age in whole years

SELECT
  id,
  DATE_PART('year', AGE(CURRENT_DATE, birth_date))::int AS age
FROM users;

You can also use EXTRACT(YEAR FROM AGE(...)). Depending on your PostgreSQL version it returns double precision or numeric, so the ::int cast keeps your output clean.

Age in days

Subtracting one DATE from another gives an integer number of days:

SELECT id, CURRENT_DATE - birth_date AS days_alive
FROM users;

Calculating Age in SQL Server

This is where most bugs come from, so slow down here.

The trap: DATEDIFF counts boundaries, not years

In SQL Server, DATEDIFF(YEAR, a, b) counts how many times you cross a 1 January between the two dates. Someone born on 31 December 2000 is reported as 1 year old on 1 January 2001, a single day after they were born.

-- WRONG for age
SELECT DATEDIFF(YEAR, '2000-12-31', '2001-01-01');  -- returns 1

The correct version

Take the DATEDIFF result, then subtract 1 if this year’s birthday hasn’t arrived yet:

SELECT
  id,
  DATEDIFF(YEAR, birth_date, CAST(GETDATE() AS date))
  - CASE
      WHEN DATEADD(YEAR, DATEDIFF(YEAR, birth_date, CAST(GETDATE() AS date)), birth_date)
           > CAST(GETDATE() AS date)
      THEN 1 ELSE 0
    END AS age
FROM users;

A compact alternative: the YYYYMMDD trick

Convert both dates to integers like 20261031, subtract, and divide by 10,000. Integer division throws away the remainder, which leaves full years:

SELECT
  id,
  ( CONVERT(int, CONVERT(char(8), CAST(GETDATE() AS date), 112))
  - CONVERT(int, CONVERT(char(8), birth_date, 112)) ) / 10000 AS age
FROM users;

Years, months, and days

SELECT
  u.id,
  m.total_months / 12 AS years,
  m.total_months % 12 AS months,
  DATEDIFF(DAY, DATEADD(MONTH, m.total_months, u.birth_date), CAST(GETDATE() AS date)) AS days
FROM users u
CROSS APPLY (
  SELECT DATEDIFF(MONTH, u.birth_date, CAST(GETDATE() AS date))
       - CASE
           WHEN DATEADD(MONTH, DATEDIFF(MONTH, u.birth_date, CAST(GETDATE() AS date)), u.birth_date)
                > CAST(GETDATE() AS date)
           THEN 1 ELSE 0
         END AS total_months
) m;

Filtering by Age Without Killing Performance

A very common task: “give me everyone who’s 18 or older.” It’s tempting to calculate age for each row and filter on the result. On a big table that forces a scan, because the database can’t use an index on birth_date once you wrap it in a function.

Flip it around. Work out the cutoff date once, then compare the raw column to it:

-- MySQL
SELECT * FROM users
WHERE birth_date <= CURDATE() - INTERVAL 18 YEAR;

-- PostgreSQL
SELECT * FROM users
WHERE birth_date <= CURRENT_DATE - INTERVAL '18 years';

-- SQL Server
SELECT * FROM users
WHERE birth_date <= DATEADD(YEAR, -18, CAST(GETDATE() AS date));

Same result, and the query can use an index.

Tip: Store the date of birth, never the age. An age column goes stale the day after you save it. Calculate it when you read the data, as shown above.

Edge Cases to Test Before You Ship

Run your query against rows like these. The table uses a fixed “today” of 31 October 2026 so the expected answers are easy to check.

Birth date Expected age on 31 Oct 2026 Why it’s a good test
1990-05-15 36 Birthday already passed this year
1995-10-31 31 Birthday is today
1995-11-01 30 Birthday is tomorrow
2000-02-29 26 Leap-day birthday, already passed
2000-12-31 25 Catches the SQL Server DATEDIFF bug

Leap-day birthdays

People born on 29 February have a “birthday” on either 28 February or 1 March in non-leap years, and different engines and methods make different choices. In SQL Server, the DATEADD pattern above treats 28 February as the birthday, while the YYYYMMDD trick treats 1 March. Pick the rule your business needs, then test it.

NULLs, future dates, and time zones

  • NULL birth dates: the result is NULL. Handle it with COALESCE or filter those rows out.
  • Future dates: bad data can produce negative ages. Add a check constraint or a WHERE clause.
  • Time zones: CURDATE(), CURRENT_DATE, and GETDATE() use the server or session clock. If your users are spread across time zones, a user can be a day “older” or “younger” than they expect around midnight.

Bonus: age in seconds

Need more precision than years? Store a full timestamp and count seconds:

-- MySQL
SELECT TIMESTAMPDIFF(SECOND, birth_datetime, NOW()) FROM users;

-- PostgreSQL
SELECT EXTRACT(EPOCH FROM (NOW() - birth_datetime))::bigint FROM users;

-- SQL Server (DATEDIFF_BIG avoids integer overflow after ~68 years)
SELECT DATEDIFF_BIG(SECOND, birth_datetime, GETDATE()) FROM users;

Frequently Asked Questions

How do I calculate age from a date of birth in SQL?

In MySQL, use TIMESTAMPDIFF(YEAR, birth_date, CURDATE()). In PostgreSQL, use DATE_PART('year', AGE(CURRENT_DATE, birth_date))::int. In SQL Server, use DATEDIFF(YEAR, birth_date, GETDATE()) minus 1 if the birthday hasn't occurred yet this year.

Why is DATEDIFF(YEAR, birth_date, GETDATE()) wrong in SQL Server?

In SQL Server, DATEDIFF(YEAR, ...) counts the number of 1st January boundaries crossed rather than full completed years. Someone born on 31 December 2000 is reported as 1 year old on 1 January 2001, just one day later.

How do I get age in years, months and days in PostgreSQL?

PostgreSQL has a built-in AGE(CURRENT_DATE, birth_date) function that returns a formatted interval containing full years, months, and days (for example, 36 years 5 mons 16 days).

What is the fastest way to find all users who are 18 or older?

Calculate the cutoff date once and compare against the raw birth_date column (e.g. WHERE birth_date <= CURDATE() - INTERVAL 18 YEAR). This allows the database query planner to utilize an index on birth_date.

How are leap day birthdays handled in SQL age calculations?

Leap day (February 29) birthdays fall on February 28 or March 1 in non-leap years depending on database engine function implementations. Always test edge case queries for leap-year behavior before deploying to production.
