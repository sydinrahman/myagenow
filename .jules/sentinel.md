## 2026-09-13 - Security Headers and Input Boundary Enforcement in Static Client-Side Web Applications
**Vulnerability:** Static web applications missing explicit Content Security Policy (CSP) headers or meta tags, combined with unbounded date string inputs in parsing logic, can leave client-side apps exposed to cross-site scripting (XSS), cross-origin leakage, or unexpected calculation errors from out-of-range inputs.
**Learning:** For static sites deployed without server-side header control (e.g. GitHub Pages or static bucket hosting), CSP directives and referrer policies must be declared via HTML `<meta http-equiv="Content-Security-Policy">` and `<meta name="referrer">` tags. In addition, date parsing functions should validate string input lengths and strict year boundaries (e.g. 1900-2100) before instantiating native `Date` objects.
**Prevention:** Always declare CSP and referrer policy meta tags across all static HTML pages and enforce strict string length and range checks on user input strings in client-side utility functions.
